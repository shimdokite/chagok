# 6일차 검토 동시 요청 측정

2026-11-27 Asia/Seoul. 로컬 PostgreSQL과 Next development, Node v24.22.3에서 실행했다. Google 로그인을 우회하는 제품 기능은 추가하지 않았으며 측정 스크립트가 임시 DB 세션을 생성했다.

- 원본: [성공 실행 20표본](../raw/day-06-1795759536591.json), [환경과 소스 해시](../environments/day-06-1795759536591.json).
- 시작: Node fetch 호출 직전 performance.now(). 끝: 응답 JSON 파싱 직후. 서버와 DB, 로컬 HTTP 포함. Google 로그인, 이미지 처리, 실제 기기 렌더 시간은 제외.
- 두 담당자가 같은 신청에 승인과 반려를 동시에 요청하는 10쌍. 각 쌍은 새 신청이며 쌍 사이에는 순차 실행. 정상 HTTP 경로는 목록/화면 확인으로 예열된 상태다.
- 결과: 10쌍 모두 성공 1건과 CONFLICT 1건. 최종 DB 상태가 성공 결정과 일치했고 같은 결정 재시도 후 감사 시각 유지. 기대한 409를 삭제하거나 네트워크 실패로 합치지 않았다.

| 결과 | n | 중앙값 ms | p95 ms | 최소–최대 ms |
| --- | ---: | ---: | ---: | ---: |
| 성공 HTTP 200 | 10 | 11.62 | 26.13 | 10.52–26.13 |
| 충돌 HTTP 409 | 10 | 12.97 | 40.09 | 11.47–40.09 |
| 전체 | 20 | 12.60 | 26.13 | 10.52–40.09 |

p95는 오름차순 `ceil(0.95*n)-1` 위치, 중앙값은 짝수 가운데 두 값의 평균이다. [재계산 JSON](../../verification/day-06/measurement-summary.json)과 대조했다. 표본 수가 작고 로컬 개발 환경이므로 운영 성능이나 개선율을 주장하지 않는다.

사전 실패도 보존했다. [서버 재시작 전 0표본](../raw/day-06-1795759400621.json)은 오래된 Prisma 인스턴스의 500, [Origin 수정 전 0표본](../raw/day-06-1795759443083.json)은 승인 403으로 종료했다. 두 실행과 성공 실행 모두 남은 fixture 사용자 0을 기록했다.

실제 Supabase 비공개 저장소의 별도 합성 이미지 1회 읽기는 513.54ms, 44,888바이트 원본 일치였고 테스트 객체를 삭제했다. [원본](../../verification/day-06/remote-receipt.json). 이는 연결 검증이며 HTTP 검토 20표본의 통계에 합치지 않는다.

후속 상태: 실제 담당자 OAuth 기능 확인은 완료했지만 OAuth 시간은 측정하지 않았다. 직원 iOS/Android 화면의 갱신 도달 시간과 배포 환경의 동일 조건 표본은 미측정이다. [최신 검증](../../verification/day-06/followup/result.md).

직원 실계정 후속: 초기97,000원과 승인 후 서버 한도 유지 확인. 승인 POST200의 서버 기록55ms는 단일 개발 요청이며 이전20표본 통계에 추가하지 않는다. iOS 화면 복귀·백그라운드 갱신 완료 시점은 미측정이다. Safari 로그인·조회는 기능 확인 완료. [실행 상태](../../verification/day-06/employee-live.md).

2026-11-28 후속 반려 POST200의 서버 기록은77ms 단일 요청. 승인55ms와 모두 기능 시험 중 개발 서버 기록이며 표본 통계·앱 렌더 지연으로 사용하지 않는다. 승인 후 화면 재진입 갱신은 사용자 확인, 반려 후 앱 활성화 갱신도 사용자 확인 및 상세 화면 관찰 완료. 앱 렌더 완료까지의 시간은 미측정이다.
