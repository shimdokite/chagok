## 2일차 계획 추가 당시 — 구현 미시작 기록

기존 인증 목표에 웹 신청 UI의 도구 전환을 추가합니다. RN 화면·브릿지 계약을 유지하며 신청 저장·검증은 4일차, 사진·업로드는 5일차에 남깁니다. 하루 5~6시간 예산과의 충돌 가능성이 있어 추가 UI 작업량·검증을 별도로 계획하며, 미완료 항목을 남긴 채 2일차 전체를 완료 처리하지 않습니다. 패키지 설치·앱 코드 수정·학습 폴더 추적 제거는 아직 수행하지 않습니다.

## 2일차 초기 구현 당시 — OAuth 설정 전 기록

Google 네이티브 SDK·서버 검증·PostgreSQL 사용자/세션·SecureStore 복원/만료/로그아웃 코드와 신청 웹의 Tailwind/shadcn 전환을 구현했다. 사용자 소유 OAuth client ID가 아직 없어 실제 Google 로그인과 정상 인증 세션 복원 실측은 미검증이며 2일차 전체 완료가 아니다. 기존 1일차의 비활성 Google 문구는 당시 기록이다. 현재 설정이 없는 환경에서는 Google 버튼을 비활성으로 안내하고 데모는 계속 제공한다. 홈·내역은 로그인 후에도 데모 표시이며 3일차 기능을 구현하지 않았다. 상세 결과는 [2일차 검증](verification/day-02.md)을 따른다.


## 3일차 구현 범위

실제 로그인과 익명 데모를 분리한다. 로그인 사용자는 서버에 등록된 소속1개로 해당 월 정책·본인 신청을 읽고, 미소속/정책 없는 달/빈 내역을 구분한다. 홈은 집계와 최근2건을 단일 요청으로 제공한다. 사용일의 KST 월 기준으로 대기·승인을 한 번 차감하고 반려는 제외한다. 내역은 월/상태·안정 커서, 상세는 반려 사유, 안내는 회사별 한도·카테고리·지침을 제공한다.

로컬 샘플 회사2개를 제공하지만 실제 로그인 계정은 자동 연결하지 않는다. 신청 화면은 비활성 예시이며 실제 금액은 홈에서 확인한다. 신청 생성/저장·첨부·승인 mutation은 각각4/5/6일차 범위다.
