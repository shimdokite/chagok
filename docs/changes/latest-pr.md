## 요약

직원이 복지비 신청에서 영수증을 선택하거나 촬영해 첨부할 수 있다. 서버는 이미지를 비공개 로컬 저장소에 보관하고 신청자의 회사와 첨부 소유권을 확인한 뒤 신청에 연결한다.

## 내용

사용자가 요청한 “Android 로컬 연결 설정과 신청 화면 브릿지 오류”를 에뮬레이터에서 재현했다. 로컬 서버에 연결한 뒤에도 동일 URL의 방문 기록 갱신이 신청 화면의 연결을 끊는 문제를 수정했다.

## 변경

- 앱에 영수증 선택·촬영·업로드와 웹 폼의 교체·제거 처리를 추가했다. iOS에서 금액 단위가 가려지던 입력 필드도 조정했다.
- 서버에 JPEG·PNG 검증, 첨부 상태와 신청 연결 트랜잭션, 만료된 미연결 첨부를 정리하는 CLI를 추가했다.
- Android 로컬 모드에서 에뮬레이터용 서버 주소를 허용했다. WebView 패치가 발신 프레임을 확인하고 동일 URL의 방문 기록 변경 후에도 연결을 유지한다.

## 검증

- 자동 검사 충족. PR 준비 시 Node 24에서 로컬 PostgreSQL 포함 36파일 333테스트 통과, 건너뜀 0개. 스타일 132파일 위반 0건, 4개 워크스페이스 타입 검사와 Next.js 프로덕션 빌드(webpack) 통과.
- iOS 시뮬레이터 검증 충족. 앞선 기기 검증에서 Debug 앱의 첨부·교체·신청과 Release 앱의 새 로그인·업로드·입력 표시를 확인했다.
- Android 로컬 브릿지 검증 충족. 앞선 Pixel 7 API 36 Release 검증에서 데모 신청 화면 25초 연결 유지, 새로고침, 닫기와 재연결을 확인했다.
- 게시 범위 충족. 로컬 학습 폴더와 인계 메모를 제외했다. 코드·문서의 공백 검사는 통과했다. 원본 로그 출력과 배포용 패치의 문맥 줄에는 Git 공백 경고가 남는다.
- 미검증. Android 실제 계정 로그인·첨부·실측은 OAuth 등록 후, 실기기 촬영·권한 복귀와 원격 저장소는 해당 환경 준비 후 확인한다. 실제 세션 만료·소속 변경 화면은 전용 테스트 계정에서 확인할 예정이다.

상세 결과는 `docs/verification/day-05.md`, 측정 조건과 표본은 `docs/metrics/daily/day-05.md`에 기록했다.

## 사이드이펙트 검토

기존 신청의 첨부 열은 nullable이다. 새 서버를 배포하려면 먼저 DB 마이그레이션과 영속적인 비공개 저장 경로가 필요하다. 정리 CLI의 예약 실행은 별도 운영 작업이다. Android 배포 빌드는 로컬 모드를 해제하고 prebuild해야 하며, 발신 프레임 검사를 지원하지 않는 구형 System WebView에서는 신청 화면 연결이 제한된다.
