## 승인 HTML 회귀 M12 — 완료

2026-11-13 사용자 확인: “직접 테스트해봤고 신청·승인·반려 모두 정상 동작해.” AC15를 완료로 확정했습니다. 아래 절차는 향후 회귀 확인용으로 보존합니다. 사용자가 별도로 언급하지 않은 경계 조건은 기존 자동 테스트 근거를 유지합니다.

사용자 요청으로 원본 작업 파일의 iframe에 `allow-forms`를 추가했습니다. 수정 전 파일은 `verification/prototype/chagok-prototype.before.html`에 보존했습니다. localhost:3000/apply는 여전히 1일차 비활성 폼이며, 아래 3015 주소가 조작 가능한 시안입니다.

- [승인 테스트 — 초기 65,000원](http://127.0.0.1:3015/chagok-prototype.html?manual=approve-1)
- [반려 테스트 — 초기 65,000원](http://127.0.0.1:3015/chagok-prototype.html?manual=reject-1)

두 주소는 같은 HTML을 제공하지만 쿼리별로 저장 상태가 분리됩니다. Chrome에 두 탭을 열고 각각 초기 65,000원을 확인해 두었습니다. 새로고침은 상태를 보존하므로, 다시 처음부터 검사하려면 주소 끝의 `approve-1`/`reject-1`을 아직 쓰지 않은 `approve-2`/`reject-2`처럼 바꿉니다.

1. 승인 링크에서 **복지비 신청하기**를 누릅니다. 사용일 `2026-11-13`, 금액 `20000`, 내용 `승인 수동 테스트`를 입력합니다.
2. 영수증을 첨부하지 않고 신청합니다. 버튼 위 **“영수증을 먼저 첨부해 주세요.”**를 확인합니다. 팝업이 아닌 폼 안의 안내입니다.
3. **영수증 촬영·선택**으로 샘플을 첨부하고 신청합니다. **“신청이 접수됐어요”**, 잔여 **45,000원**을 확인합니다.
4. 상단 **담당자 웹** → 방금 작성한 항목의 **검토하기** → **승인하기**. **승인 완료**를 확인하고 상단 **홈**에서 **45,000원** 유지, **내역**에서 해당 항목의 승인 상태를 확인합니다.
5. 별도 반려 링크에서 초기 **65,000원**을 확인한 뒤, 내용 `반려 수동 테스트`로 같은 20,000원 신청을 합니다.
6. **담당자 웹** → 해당 항목 **검토하기** → 사유 없이 **반려하기**를 눌러 필수 안내를 확인합니다. 사유를 입력하고 다시 반려합니다.
7. **홈**에서 **65,000원** 복원, **내역**에서 해당 항목의 **반려** 및 상세 사유를 확인합니다.

기존 `file:///Users/doyeon/Desktop/chagok/docs/design/chagok-prototype.html`도 수정된 파일을 다시 읽도록 새로고침해야 합니다. Codex의 실제 검증 환경은 로컬 HTTP + Chrome이며 file URL과 다른 브라우저는 별도 실행 검증하지 않았습니다. 샘플 첨부·신청·승인·반려는 시안의 가상 상태 변경이고 실제 앱 신청 기능 구현 증거가 아닙니다.
