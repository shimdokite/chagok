## 실행한 검증 — 5그룹

환경: macOS arm64, 프로젝트 Node v24.22.3, Next16.4.6, 로컬 PostgreSQL 127.0.0.1:55432/chagok, Device Hub Chagok M09 Mini/iOS27.2. Next3000·native Metro8081·웹 미리보기8082의 기존 실행을 확인했다.

1. **전체 테스트·DB·스타일 — 통과.** Node의 `--env-file=apps/web/.env.local`로 환경을 읽고 자식 npm에 `CHAGOK_TEST_DATABASE_URL=DATABASE_URL`을 전달해 `npm test` 실행. 최초 일반 실행은 DB 연결 EPERM으로 151통과/2실패. 허용된 재실행은 **17파일153개 통과·skip0**, pretest87파일 위반0. [최종 로그](tests.log). 실패를 테스트 코드 결함으로 판단하거나 건너뛰지 않았다. DB 테스트는 고유한 임시 사용자/세션과 명시적 sample fixture를 사용하고 자체 finally 정리를 수행한다. 실제 Google 사용자 소속을 바꾸지 않았다.
2. **타입·기본 빌드 — 타입 통과, 빌드 실패.** `npm run typecheck` 4개 워크스페이스 exit0 ([로그](typecheck.log)). `npm run build:web` 일반 실행 및 허용된 재실행 모두 CSS worker가 새 프로세스의 포트에 바인딩하는 단계에서 `Operation not permitted (os error 1)`로 exit1 ([일반](build.log), [재실행](build-escalated.log)). 이번에도 기본 Turbopack 성공은 확인하지 못했다. 이전 webpack/export 성공 로그는 과거 기록이며 이번에 다시 실행하지 않았다.
3. **iOS 다크·큰 글자 — 부분 확인.** 기존 Light/Text Size3에서 시작해 Dark/11(최대)로 변경했다. 실제 어두운 배경·확대된 글자 렌더를 관찰했다. 접근성 버튼 클릭으로 홈→내역→반려 필터→운동 이용권 상세(30000원·반려 사유)→정책을 확인했다. 이는 직접 터치/스크롤과 동일한 검증이 아니다. 최대 크기에서 하단 '신청 내역/복지 안내'가 여러 줄로 세로 배치되어 본문 영역을 많이 차지했다. 잘림 여부와 본문 끝 접근성은 직접 스크롤로 추가 확인해야 한다. 스크롤은 좌표/요소 대상과 창 Raise 후에도 `noWindowsAvailable`로 실패했다. 앱 스크롤 실패로 단정하지 않는다. 글자3/Dark 정책 화면의 금액·카테고리 표시를 확인했고 종료 전에 Light/3으로 복구했다. [다크 정책](ios-dark-policy.png), [최대 글자](ios-max-text-policy.png).
4. **로그인·브라우저·플랫폼 — 분리 판정.** iOS 데모를 종료하고 Google 로그인 버튼으로 OS 로그인 확인창에 도달했다. 자동 승인 검토가 '계속' 클릭을 거부했으며 실제 계정 정보 공유/로그인은 사용자 직접 수행이 필요하다는 사유였다. 우회하지 않고 사용자에게 직접 로그인 완료 여부를 요청했다. 계정 선택/비밀번호 입력/회사 연결은 하지 않았다. Chrome8082는 데모 홈65000원·최근2건을 확인하고 열어 두었다 ([화면](browser-home.png)). RN Web의 Google 버튼은 비활성으로 네이티브 로그인 검증을 대체하지 않는다. `command -v adb`, 표준 SDK 경로 확인에서 ADB/SDK를 찾지 못해 Android 실제 실행은 미실행. 물리 iPhone/Android 기기 실행도 이번 범위에서 확인하지 못했다.
5. **문서·보존 — 통과.** 검증/수동 확인과 최신 PR·커밋 초안을 갱신했다. 원본 Day3 로그·소스 해시는 과거 증거로 보존했다. git diff --check 및 문서 링크·초안 필수 절 확인. 앱/API/스크립트의 tracked diff는 시작 기준과 동일하며 staged diff와 학습/과거 PR 문서 diff는 비어 있다.

## 사용자가 이어서 할 일

[수동 확인의 최신 후속 절](../../../manual-checks.md#3일차-미검증-후속--2026-11-17)을 따른다. 사용자가 직접 Google 로그인을 완료했으며 개발자가 홈·내역·정책의 미소속 안내를 확인했다. 실제 계정의 샘플 회사 연결은 본인 User.id와 회사 선택이 명확한 별도 작업이다. 새 로그인만으로 자동 소속이 생기면 안 된다.

회사 연결 뒤 실제 계정의 홈·내역·정책, 네트워크 오류→재시도, 로그아웃→다른 계정 화면은 아직 미검증이다. 자동 DB/캐시 테스트의 통과를 기기 UI 통과로 대체하지 않는다.

## 사이드이펙트

앱·API·스키마·의존성은 이번 작업에서 변경하지 않았다. 테스트 fixture 및 임시 데이터 생성/정리는 기존 테스트가 수행하며 개인 계정의 소속·정책을 임의 수정하지 않았다. Device Hub 표시 설정은 원복했다. Next 빌드 산출물은 로컬 생성물이고 이전 production 결과를 보장하지 않는다. 사용자 터미널의 기본 빌드 성공 결과 또는 전체 오류 로그가 있어야 환경 제한인지 다른 빌드 문제가 남는지 최종 구분할 수 있다.

## 실제 로그인 완료 후 추가 확인 — 2026-11-17

사용자의 로그인 완료 응답 후 Device Hub의 실제 앱 화면을 다시 읽고 접근성 버튼으로 홈→신청 내역→복지 안내→홈을 이동했다. Google 로그인 조작은 사용자가 수행했으며, 이전 자동 승인 검토 거부를 우회하지 않았다.

회사 선택 응답 전에는 DB 소속/신청을 변경하지 않는다. 로그인 성공만으로 D3-04 전체를 충족 처리하지 않는다. 회사 연결 후 실제 조회·네트워크 복구·다른 계정 격리, 최대 글자 직접 스크롤, Android 실행, 기본 Turbopack 빌드는 여전히 미검증이다.

이번 추가 확인은 앱 코드 수정 없는 화면 검증·문서 갱신이므로 테스트/타입/빌드를 다시 실행하지 않았다. 위 153개 테스트 등의 결과는 앞선 후속 실행 기록이다. 새 서버·브라우저 실행은 해당 없음 — 기존 iOS 앱을 확인하고 로그인된 미소속 홈에 두었다. 이번 시작 기준 diff는 `/tmp/chagok-login-followup-baseline.diff`에 보관했다. Git diff 공백·초안 형식·로컬 링크 검사와 앱/API/스크립트 tracked diff 보존 여부를 별도 확인했다.
