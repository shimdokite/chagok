## 검증 근거

1. Node24 `npm test -- apps/mobile/src/benefits/BenefitsProvider.test.tsx apps/mobile/src/benefits/cache.test.ts apps/mobile/src/benefits/queries.test.ts --maxWorkers=2`:23:55 KST,3파일15테스트 통과, exit0. pretest 스타일149파일0위반. 제품 코드 변경이 없어 전체 테스트·빌드·타입 검사를 반복하지 않았다.
2. 로컬 Prisma 읽기 대조: 최종 승인1,000원 APPROVED/반려2,000원 REJECTED, 사용 가능99,000원 및 두 결정 감사 필드 확인. [식별자 없는 결과](followup/employee-data-check.json). 기존13건/4소속의 전체 필드 불변, 신규2건/1소속만 허용 assertion.
3. 실제 화면: [담당자 승인](followup/employee-approved.jpg), [Safari 인증 후 상세](followup/safari-authenticated.jpg), [Safari 반려](followup/employee-rejected-safari.jpg), [직원 앱 반려 상세](followup/employee-ios-rejected.jpg). 직원 초기 신청 목록은 Device Hub 스크린샷으로 관찰했다. Device Hub 내부 좌표 클릭은 Raise 후에도 `noWindowsAvailable`이 발생해 사용자에게 앱 탭 이동과 백그라운드 전환을 요청했다.
4. 측정 제한: 서버 로그의 승인 POST200은55ms, 반려 POST200은77ms로 각각 단일 개발 요청. 사용자 탭 동작과 렌더 완료 사이 타이밍은 계측하지 않아 앱 갱신 지연 수치나 p95를 주장하지 않는다. [측정 범위](../../metrics/daily/day-06.md).

## 완료 범위와 남은 항목

승인 후97,000원·승인 완료는 사용자 확인 및 직접 관찰 완료. 에이전트가 Device Hub Home 버튼으로 앱을 백그라운드에 두고 새2,000원 건을 반려했다. 사용자가 차곡으로 복귀해 새로고침 없이99,000원·반려·사유를 확인했고 에이전트도 최종 상세 화면을 관찰했다. iOS 화면 재진입·앱 활성화 경로와 Safari 로그인·상세·영수증·반려 처리는 완료했다.

Android는 최신 Release 빌드·설치까지만 검증됐으며 같은 실제 직원 계정 로그인과 갱신 화면 검증이 남았다. 기본 Turbopack 빌드 EPERM도 남아 있다. 테스트용 두 신청은 승인/반려 상태로 로컬에 보존하며 실제 송금은 없다. 앱 소스·OAuth 설정 변경 없이 데이터 준비와 검증 문서를 갱신했다. 커밋·push·PR 생성은 수행하지 않았다.
