# Android 직원 앱 후속 검증

2026-11-28 00:21~00:31 KST. 기존 Chagok_API_36 에뮬레이터(API 36, arm64)와 Release 앱, 로컬 Next/PostgreSQL로 확인했다. 사용자가 직원 테스트 Google 계정 로그인을 직접 완료했고 에이전트가 이후 화면 조작과 검증을 수행했다. 물리 Android 기기는 없어 검증하지 않았다.

## 환경과 변경

- 설치된 `dev.doyeon.chagok` APK와 최신 Release 산출물의 SHA-256은 `2488a96a3a35634e40ce8e1492b04e778db83de7912f6167858a19ad42cf44c5`로 일치했다. 이 작업에서는 앱을 다시 빌드하거나 제품 코드를 변경하지 않았다.
- 앱 API 원본은 `http://10.0.2.2:3000`, 담당자 웹은 `http://localhost:3000/admin`이다. 기존 개발 서버와 DB를 사용했다.
- 기본 화면 제어 도구가 에뮬레이터 창을 인식하지 못해 사용자에게 명시적으로 ADB 사용 승인을 받았다. 기존 담당자 앱 세션을 로그아웃하고 사용자에게 직원 Google 로그인을 넘겼다. 로그인 후 그로브, 99,000원과 해당 직원의 새 세션 생성 시각을 대조했다. 계정 이메일과 인증 정보는 증거 파일에 기록하지 않는다.
- 기존 직원 소속을 유지하고 합성 PNG 영수증이 있는 `[Android 테스트]` 신청 두 건만 추가했다. 1,000원은 승인, 2,000원은 반려했다. 실제 송금은 없으며 로컬 테스트 결과를 보존했다.

## 검증 근거

1. **화면:** [초기 잔액](android/initial-home.png), [초기 두 신청](android/initial-history.png), [승인 후 잔액](android/approved-home.png), [승인 후 내역](android/approved-history.png). 초기 데이터 준비 외에 검토 결과 확인 중 새로고침 버튼은 사용하지 않았다.
2. **앱 복귀:** [Home 전환 직후 캡처](android/background.png), [담당자 반려](android/admin-rejected.png), [복귀 후 98,000원](android/rejected-home.png), [반려 내역](android/rejected-history.png), [반려 사유 상세](android/rejected-detail.png). `dumpsys activity`에서 `mResumedActivity`를 추출하려던 [기록](android/lifecycle.log)은 비어 있어 activity 전환의 근거로 사용하지 않는다. Home 키 직후 캡처는 아직 차곡 전환 중 화면이므로 Launcher 정착 증거로 사용하지 않는다. 테스트 경로는 ADB Home 키 실행 후 별도 담당자 반려, 기존 task 재개와 앱 잔액/사유 관찰에 근거하며 OS activity 로그 검증은 미완료다. `am start` 결과도 새 Activity 시작이 아니라 기존 task를 전경으로 가져왔음을 확인했다.
3. **DB:** [식별자 없는 결과](android/data-check.json). 승인 시각 00:29:39, 반려 시각 00:30:21 KST. 기존 15신청/5소속 전체 필드 불변과 신규 2건만 허용하는 assertion을 실행했다. 계정 식별자와 원본 기준 스냅샷은 `/tmp` 권한600 파일로만 보존한다.
4. **자동 회귀:** 00:21:30 KST, Node24에서 `npm test -- apps/mobile/src/benefits/BenefitsProvider.test.tsx apps/mobile/src/benefits/cache.test.ts apps/mobile/src/benefits/queries.test.ts --maxWorkers=2` 실행. 3파일 15테스트 통과, exit0. pretest 스타일149파일 위반0. [원본](android/regression.log). 이번 Android 작업 중 로그인 대기 전에 실행한 결과이며 제품 코드 변경이 없어 이후 전체 테스트·타입·빌드를 반복하지 않았다.
5. **문서와 제외 정책:** 상대 링크·필수 초안 형식·공백 검사와 학습 경로의 추적/staged/기준 브랜치 diff 제외를 확인했다. 제품 UI 변경은 없어 별도 새 화면 인수는 해당 없음이며 기존 앱의 실제 동작을 위 경로에서 직접 검증했다.

## 측정과 한계

이 실행은 각 플랫폼 동작의 기능 검증이다. 탭 또는 앱 활성화부터 렌더 완료까지의 시간을 계측하지 않아 갱신 지연이나 p95를 산출하지 않는다. 기존 [HTTP 20표본 측정](../../metrics/daily/day-06.md)에 이번 수동 요청을 추가하지 않았다. 에뮬레이터 통과를 물리 기기 통과로 일반화하지 않는다.

iOS와 Android 에뮬레이터의 직원 자동 갱신 검증은 완료했다. 기본 Turbopack은 일반 macOS 터미널에서 성공했고 Codex 실행 환경의 EPERM 제한은 남는다([진단](turbopack.md)). 이번 변경은 검증 자료와 문서이며 커밋·push·PR 생성은 수행하지 않았다.

## 사용자가 다시 확인하는 순서

1. 열려 있는 Android 차곡 앱에서 `홈`을 눌러 98,000원, 검토 중 0원, 승인 2,000원을 확인한다.
2. `신청 내역`에서 `[Android 테스트]` 두 건의 승인 완료와 반려를 확인한다.
3. 2,000원 반려 건을 열어 “Android 테스트: 사용일과 금액이 보이는 영수증으로 다시 신청해 주세요.”를 확인한다.
4. 담당자 웹에서 동일 두 건의 처리 결과를 확인한다. 기존 테스트 결과를 되돌리거나 다시 처리할 필요는 없다.

## 사용자 직접 확인 — 2026-11-28

사용자가 안내한 `홈 → 98,000원 → 신청 내역 → Android 2,000원 반려 상세` 순서를 직접 확인했다고 응답했다. 이는 앞선 에이전트 자동 갱신 검증에 추가된 사용자 수동 확인이며, 사용자에게 상태 전이 실험을 다시 수행했다고 해석하지 않는다. 물리 기기 미검증과 렌더 지연 미측정은 유지한다.
