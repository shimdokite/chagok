# 실제 Google 로그인·담당자 처리 확인 — 2026-11-27

사용자 요청: “이제 로그인되는지 확인하고 테스트 이어가자.” 기존 개발 서버와 실제 Google 계정으로 Chrome에서 로그인·승인·반려·로그아웃·재로그인·새로고침을 확인했다. 앱 소스와 환경 파일은 수정하지 않았다.

## 원인과 조치

초기 재시도에서도 `401 invalid_client / no registered origin`이 재현됐다. 실제 요청 origin은 `http://localhost:3000`이었으며 웹/모바일 client ID는 일치했다. Chrome의 기존 Google Cloud 콘솔을 읽어 보니 두 주소가 승인된 리디렉션 URI에 있었고 JavaScript 원본은 비어 있었다. 사용자가 리디렉션 URI에 추가했음을 확인했다.

에이전트는 JavaScript 원본에 첫 주소 입력과 두 번째 칸 추가까지만 수행했다. 그 사이 사용자 조작으로 저장 화면이 닫혔고 저장 완료 알림이 표시됐다. 다시 연 설정에서 `http://localhost`, `http://localhost:3000` 두 주소가 승인된 JavaScript 원본에 저장되고 리디렉션 URI는 비어 있음을 확인했다. 에이전트는 저장 버튼을 누르지 않았다. 새 요청은 Google 계정 인증 단계로 진행됐다.

앱 내 브라우저에서는 Google 반환 주소 `/gsi/transform`이 빈 화면에 머물렀고 앱 로그인 완료는 확인하지 못했다. Chrome에서는 기존 실제 계정 선택 후 그로브 목록까지 진입했다. 두 브라우저 차이의 원인은 이번에 확정하지 않았으며 앱 내 브라우저 문제를 해결했다고 주장하지 않는다. Google 설정 변경 반영에는 시간이 걸릴 수 있다([공식 안내](https://support.google.com/cloud/answer/15549257)).

3. **문서·보존:** 문서 링크/초안 형식, git diff --check, 학습 경로 ignore·추적/staged/origin/main 대비 제외를 확인했다. 시작 diff는 `/tmp/chagok-oauth-retest-before.diff`, staged diff는 `/tmp/chagok-oauth-retest-staged-before.diff`에 기록했다. 기존 소스 diff를 보존했다. 커밋·push·PR은 수행하지 않았다.

## 영향과 남은 확인

연습용 신청 두 건은 이제 승인 완료/반려 상태이며 UI에서 되돌리는 기능은 없다. 다른 기존 신청은 처리하지 않았다. 개인 계정의 Google 로그인 세션을 Chrome에 남겨 직접 확인할 수 있게 했다. 실제 송금이나 운영 데이터 처리는 없다. 가상 직원은 Google 로그인 계정이 아니므로 실제 직원 앱의 처리 결과·잔액 갱신은 별도 실제 테스트 직원 계정으로 확인해야 한다. 로컬 학습 자료는 Git/PR 제외 상태다.

## 사용자 확인과 본인 신청 조회 후속 확인 — 2026-11-27

사용자는 1,000원 연습용 도서비의 승인 완료·영수증 상세, 승인/반려 필터의 처리 결과와 반려 사유를 직접 확인했다고 보고했다. 이어 “본인 신청은 따로 내역이 없는 것 같은데”라는 피드백에 따라 기존 Chrome 세션의 `/admin`을 읽기 전용으로 확인했다.

- **O1 충족 — 본인 신청 존재·조회 경로:** 사용 월 `2026-11`, 신청 상태 `전체`에서 현재 본인 신청자의 짧은 표시와 일치하는 5건이 표시됐다. `Android receipt QA 1125` 1원(검토 중), `DAY05 UI TEST 20261123` 1,000원(검토 중), `업무 역량을 위한 도서` 15,000원(검토 중), `복지 이용` 20,000원(승인 완료), `증빙 확인이 필요한 신청` 30,000원(반려). 목록에는 본인 배지나 별도 본인 탭이 없고 다른 직원과 동일한 `직원 + 짧은 ID` 형식으로 표시되어 구분하기 어렵다. 신청 소유자 비교는 서비스의 `isOwn`으로 제공되고 상세 UI에서 사용된다. 데이터 누락은 재현되지 않았다.
- **O2 충족 — 자기 신청 처리 차단:** `Android receipt QA 1125`의 검토하기를 열어 영수증과 “본인 신청은 다른 담당자가 검토해야 해요.” 안내, 승인·반려 버튼 미노출을 실제 Chrome 화면에서 재확인했다. 해당 상세를 열어 두었다. 이번에는 신청 상태나 DB를 변경하지 않았다.
- **O3 충족 — 확인 주체 구분:** 승인·영수증·필터·반려 사유는 사용자 직접 확인으로 기록한다. 본인 신청 상세는 이번 에이전트 브라우저 확인이며, 사용자 본인의 직접 확인 완료로 대신 기록하지 않는다.

이번 검증은 ① Chrome 목록·상세 관찰과 서비스/UI 코드 대조 ② 사용자 직접 확인 보고 반영 ③ 문서 형식·링크, `git diff --check`, 학습 경로 Git 제외 확인의 3그룹이다. 앱 소스·설정 변경이 없어 테스트 스위트·스타일·타입·빌드는 재실행하지 않았다. 시작 diff `/tmp/chagok-own-claims-before.diff`와 대조해 기존 소스 변경을 보존했다. 화면 변경은 해당 없음이며 기존 개발 서버에서 조회했다. 기존 앱 내 브라우저·네이티브 미검증 항목은 이번 확인으로 해소되지 않는다.

## 사용자 최종 확인과 추가 검증

사용자는 본인 신청 안내까지 직접 확인했다고 보고했다. 따라서 위 O3의 본인 신청 사용자 확인 대기도 해소됐다. 이후 Chrome 취소/재시도, 현재 내장 브라우저 세션, 네이티브 빌드와 남은 사용자 조작은 [후속 검증](followup/result.md)에 기록한다.
